Answer hints

Q1(g). Fair scheduler vs capacity scheduler

The fair scheduler shares cluster resources so every running job gets an equal share over time. The capacity scheduler divides the cluster into queues, each guaranteed a set percentage, which suits several teams sharing one cluster. Spare capacity in one queue can be lent to others.

Q2(d). NoSQL vs RDBMS

RDBMS: fixed schema, tables and joins, ACID transactions, scales up on one bigger server. NoSQL: flexible schema, scales out across many servers, often trades strict consistency for availability (BASE). Types: document (MongoDB), key–value (Redis), column-family (HBase, Cassandra), graph (Neo4j). Use cases: real-time web apps, IoT data, catalogues, social feeds.

Q5(a). HDFS data replication

Each block is stored on several DataNodes, 3 by default. With rack awareness, one copy goes on the local rack and two on another rack, so a whole rack can fail without data loss. The NameNode tracks replicas through heartbeats and re-replicates blocks when a node dies. Advantages: fault tolerance, high availability and faster parallel reads.

Q6(a). MongoDB create, update, delete

Create: db.students.insertOne({name: "Asha", marks: 82}). Update: db.students.updateOne({name: "Asha"}, {$set: {marks: 90}}). Delete: db.students.deleteOne({name: "Asha"}). Mention insertMany, updateMany and deleteMany for multiple documents, and that documents are stored as BSON.
